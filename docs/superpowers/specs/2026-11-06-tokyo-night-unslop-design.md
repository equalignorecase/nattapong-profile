# แผนปรับพอร์ตโฟลิโอ: Tokyo Night

สถานะ: ผู้ใช้อนุมัติแบบและสั่งให้ลงมือแล้ว

## เป้าหมาย

ให้ HR และทีมพัฒนาอ่านบทบาท ทักษะ และผลงานได้รวดเร็ว โดยยังคงบุคลิกเว็บนักพัฒนาและรองรับภาษาไทย

## ทางเลือกที่พิจารณา

- Tokyo Night: เก็บพื้นโทนหมึกและน้ำเงิน ลดสีรอง กรอบ และเอฟเฟกต์ เปลี่ยนจากของเดิมน้อยกว่า ผู้ใช้เลือกแนวทางนี้
- พอร์ตแบบบทความ: ลดกรอบหน้าต่างและเน้นตัวอักษรมากกว่า แต่เปลี่ยนบุคลิกเดิมมากกว่า จึงไม่เลือก

## ทิศทาง

- Product: พอร์ต Junior Full-Stack / Frontend Developer สำหรับผู้พิจารณารับเข้าทำงาน
- Character: รอบคอบ ตรงไปตรงมา เป็นมิตร
- World: สมุดบันทึกงานพัฒนาและรายละเอียดทางวิศวกรรม
- Moments: ชื่อและบทบาทที่อ่านชัด และรายการผลงานที่ให้เนื้อหานำสายตา
- Signature: เลขลำดับโปรเจกต์แบบ mono ใช้ตรงกันในหน้ารวมและหน้ารายละเอียด

## ขอบเขตและข้อจำกัด

ปรับหน้าแรก หน้ารายละเอียดโปรเจกต์ และองค์ประกอบร่วม โดยใช้ Astro, Tailwind และโครงสร้างข้อมูลเดิม คงลำดับแนะนำตัว → ผลงาน → ทักษะ → การศึกษา → ติดต่อ และคงโหมดสว่าง/มืด

ยังไม่เพิ่มฟีเจอร์ เปลี่ยนข้อมูลประวัติ สร้างภาพด้วย AI ทำวิดีโอ หรือนำเว็บขึ้นออนไลน์ ไม่เพิ่ม dependency หากองค์ประกอบเดิมและ inline SVG เพียงพอ

## แบบที่เสนอ

1. **ระยะ:** ใช้สเกล 4px เป็นหลัก ระยะกลุ่ม 16–24px และระหว่างส่วน 48–64px ขอบจอมือถืออย่างน้อย 16px ปุ่มสำคัญสูงอย่างน้อย 44px
2. **สี:** พื้นโทนหมึกความอิ่มสีต่ำ ข้อความสามระดับ และน้ำเงินเป็นสีเน้นหลัก ตัดแสงฟุ้ง ตารางพื้นหลัง เงาสี และแถบตัวอย่างสี สีเขียวใช้เฉพาะสถานะพร้อมทำงานแบบนิ่ง ตรวจ contrast ข้อความอย่างน้อย 4.5:1
3. **ไอคอน:** ใช้ line SVG รูปแบบเดียวกัน ขนาด 16–18px stroke 1.5 และสีตามข้อความ ตัดไอคอนที่ไม่ช่วยสื่อความ
4. **ข้อความ:** ย่อชื่อส่วนและปุ่ม ลดการแปลไทย/อังกฤษซ้ำ คงศัพท์เทคนิคที่จำเป็น ไม่เพิ่มคำกล่าวอ้างหรือผลลัพธ์
5. **ตัวอักษร:** เก็บ Anuphan สำหรับภาษาไทย และ JetBrains Mono สำหรับข้อมูลกำกับ ใช้น้ำหนัก 400/500 และ 600 เฉพาะจุด ข้อความหลัก 16px พร้อมระยะบรรทัดที่เหมาะกับภาษาไทย ชื่อประมาณ 36–44px บนเดสก์ท็อป และ 28–32px บนมือถือ ปรับตามชื่อจริงโดยไม่ตัดข้อความ
6. **โครงหน้า:** เก็บกรอบหน้าต่างหลักในรูปแบบเรียบ ลดกล่องซ้อนใน Hero รวมข้อมูลเบื้องต้นให้กระชับ ปุ่มหลัก “ดูผลงาน” และปุ่มรอง “เรซูเม่” ส่วนติดต่อเข้าถึงผ่านเมนูและส่วนติดต่อเดิม บนมือถือเมนูยุบและเนื้อหาเรียงตามลำดับการอ่าน
7. **รายละเอียด:** รายการผลงานเน้นชื่อ คำอธิบาย และสิ่งที่พัฒนา ป้ายเทคโนโลยีและปีใช้สีสงบ ปุ่มหลักเด่นเพียงหนึ่งต่อกลุ่ม รัศมีปุ่ม 8px การ์ด 12–16px เพิ่ม focus ที่มองเห็นชัด และตั้งค่า aria ของ theme toggle ให้ตรงกับสถานะตั้งแต่โหลดหน้า
8. **ภาพ:** ไม่มีภาพผลงานจริงในไฟล์ที่ตรวจพบ จึงให้เนื้อหาผลงานเป็นจุดเด่น ไม่สร้างภาพหน้าจอหรือข้อมูลจำลอง ภาพจริงเพิ่มภายหลังได้เมื่อผู้ใช้มีให้
9. **การเคลื่อนไหว:** ตัด pulse และ transition-all ใช้การเปลี่ยนสี/พื้น/เส้นขอบประมาณ 160ms และรองรับ prefers-reduced-motion

ค่าตัวเลขและวิธีจัดองค์ประกอบข้างต้นเป็นข้อเสนอของผู้ช่วย ไม่ใช่ข้อกำหนดเพิ่มเติมจากผู้ใช้

## ข้อมูลที่ยังต้องยืนยัน

ชื่อ สถานศึกษา ข้อมูลติดต่อ และ URL ในข้อมูลปัจจุบันเป็นตัวอย่าง ไม่เติมข้อมูลจริงเอง ไม่พบ public/resume.pdf จากรายการไฟล์ที่ตรวจ จึงต้องตรวจลิงก์นี้อีกครั้งก่อนเผยแพร่

ตัวเลขผลลัพธ์ เช่น ลดเวลา 40%, coverage 88% และ Lighthouse 100 ยังไม่ได้รับการยืนยัน ข้อเสนอคือซ่อนเฉพาะคำกล่าวอ้างเชิงตัวเลขที่ยังไม่ยืนยันจากหน้าที่แสดง โดยเก็บข้อมูลต้นฉบับไว้ และคงคำอธิบายงานที่พัฒนา

## ไฟล์ที่คาดว่าจะปรับ

- src/styles/global.css: สี ระยะ ฟอนต์ และองค์ประกอบร่วม
- src/layouts/BaseLayout.astro: กรอบหลัก เมนู และส่วนท้าย
- src/components/ThemeToggle.astro: รูปลักษณ์และสถานะ accessibility
- src/pages/index.astro: Hero และส่วนเนื้อหาแต่ละส่วน
- src/pages/projects/[id].astro: รูปแบบหน้ารายละเอียดให้สอดคล้องกัน
- tailwind.config.mjs: เฉพาะเมื่อจำเป็นสำหรับ token ที่ใช้ร่วมกัน

## เกณฑ์ตรวจรับ

รัน npm run build ให้ผ่าน ตรวจหน้าแรกและหน้ารายละเอียดทุกโปรเจกต์ ตรวจ dark/light ที่ความกว้างประมาณ 390px และ 1440px ไม่มี horizontal overflow อ่านภาษาไทยไม่ถูกตัด ใช้เมนู คีย์บอร์ด ปุ่มสลับธีม และลิงก์ภายในได้

การตรวจครั้งแรกอ้างอิงโค้ด ยังไม่ได้ตรวจภาพจริงเนื่องจากไม่มี browser surface ในเครื่องมือ หากยังเปิดเบราว์เซอร์ไม่ได้ตอนลงมือ ต้องรายงานข้อจำกัดในการตรวจภาพอย่างชัดเจน

## ลำดับงานหลังอนุมัติ

เขียนแผน implementation จากแบบนี้ จากนั้นปรับตามเก้าลำดับข้างต้น ตรวจ build และภาพจริง สรุปผลพร้อมรายการข้อมูลที่ต้องแทนก่อนเผยแพร่
